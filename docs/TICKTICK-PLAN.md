# 对标 TickTick 的功能实现方案

> 目标：把现有 `dsh-sidebar-todo`（MVP：单清单 + 快速添加 + 到期提醒）演进为一个 DSH 内的 TickTick 式任务管理器。
> 版本基线：`dsh-sidebar-todo 0.2.0`（P0 已落地），DSH `0.2.2-rc.5`。
> 原则：只借鉴 TickTick 的交互与信息架构，不复制其代码与素材；所有能力落在 DSH 现有扩展点上。

## 0. 当前进度

- **P0 已交付**（0.2.0）：v2 数据模型与 v1 迁移、清单、标签、智能清单、任务 CRUD、详情抽屉、软删除/撤销、`^清单` 语法、搜索。
- **P1 部分交付**（0.3.0）：子任务、备注、多个提醒 + 稍后、重复任务预设、标签重命名/删除、v2→v3 迁移。
- **P1 再交付**（0.4.0）：文件夹、手动排序 + 拖拽、批量完成/移动/删除、键盘快捷键、排序模式。
- **P2 部分交付**（0.5.0）：看板（按优先级/清单）、月日历（拖拽改期）、四象限、统计（30 天完成、按清单/标签）。
- **P2 追加**（0.6.0）：日历周视图、日视图（0–24 点，拖拽改到某小时）。
- **P1 剩余**：i18n（zh/en 字典）、Markdown 备注预览、窄窗口清单选择器。
- **P2 剩余**：保存筛选、增量同步、时间线/甘特。
- **下一步**：P2 剩余项，或收尾 P1 的 i18n/Markdown。

## 1. 范围与判断

TickTick 的功能很多，但不是每个都值得搬进 DSH。取舍标准：

1. **能在一个侧栏插件里闭环**（不需要服务端、不需要账号体系）。
2. **能复用 DSH 已有能力**（`ctx.schedule`、`ctx.storage`、`ctx.tools`、slots、theme、shortcuts）。
3. **对“让 agent 和用户共用一份任务”有增益**，这是 DSH 相对 TickTick 的差异点。

### 1.1 功能取舍表

| TickTick 功能 | TickTick 的做法 | 本方案 | 阶段 | 取舍理由 |
|---|---|---|---|---|
| 智能清单 | 今天 / 最近 7 天 / 收件箱 / 全部 / 已完成 | 收件箱、今天、最近 7 天、全部、已完成 | P0 | 高价值、零额外存储，按字段派生 |
| 清单 / 文件夹 | 清单树 + 文件夹 | 清单 + 单层文件夹 | P0 | 覆盖 90% 用法；无限层级收益低 |
| 标签 | 多标签、颜色 | 多标签、可改名/合并 | P0 | 与清单互补 |
| 优先级 | 无 / 低 / 中 / 高 | 无 / 低 / 中 / 高（0–3） | P0 | 现有字段升级，兼容旧数据 |
| 子任务 / 检查清单 | 任务内 checklist | 任务内 checklist（单层） | P1 | 两层足够，避免无限嵌套 |
| 备注 / Markdown | 富文本 + Markdown | Markdown 纯文本预览 | P1 | DSH 已有 Markdown 渲染习惯 |
| 到期 / 开始日期 | 日期 + 时间 + 全天 | `dueAt` / `startAt` / `allDay` | P1 | 日历视图需要 |
| 重复任务 | 每天/每周/每月/自定义 | 预设 + 自定义 RRULE（P4） | P1/P4 | 先做高频预设，RRULE 后置 |
| 多提醒 | 最多 5 个提醒、稍后提醒 | 最多 3 个提醒 + 稍后提醒 | P1 | 复用现有扫描器，改数组即可 |
| 过滤器 | 自定义筛选条件 | 保存的查询（字段+操作符） | P2 | 查询 DSL 同时服务搜索 |
| 日历视图 | 年/月/周/日/议程 | 月 / 周（本地任务） | P2 | 不接外部日历；ICS 导入后置 |
| 看板 | 按清单/标签分列 | 按清单或优先级分列 | P2 | 拖拽用原生 pointer 事件 |
| 四象限 | 艾森豪威尔矩阵 | 由“紧急=今天/逾期、重要=优先级”派生 | P2 | 纯派生视图，无新数据 |
| 时间线 | 甘特式 | 不做（P4 可选） | — | 复杂度高、侧栏空间不足 |
| 番茄钟 | 任务绑定计时 | 任务绑定 + 专注记录 | P3 | 与统计联动 |
| 统计 | 完成数、专注时长、习惯 | 完成趋势、按清单/标签、专注分钟 | P3 | 从任务与专注记录派生 |
| 习惯打卡 | 独立模块 | 不做 | — | 独立产品域，会稀释任务模型 |
| 倒数日 | 独立模块 | 不做 | — | 同上 |
| 40+ 主题 | 自带主题系统 | 不做，使用 DSH `--dsw-*` 主题 | — | 宿主统一主题 |
| 协作 / 共享 | 账号 + 服务端 | 不做 | — | 无多用户后端 |
| 位置提醒 | 移动端定位 | 不做 | — | DSH 桌面场景不适用 |
| 日历双向同步 | Google/Outlook | P4 可选 ICS 导入 | — | 需要 OAuth/同步引擎 |
| 语音捕获 | 语音转任务 | 复用 DSH 语音插件（实验性） | P4 | 不重复造轮子 |
| AI 助手 | 内置 LLM | 复用 DSH agent，不内置模型调用 | P3 | agent 就是 AI |

```
│  └────────────┘  └────────────┘  └─────────────┘  └──────────┘  └──────────────┘  │
│  JSON 存储（默认）/ 可选 ctx.storage.domain（大数据量）                              │
└───────────────────────────────────────────────────────────────────────────────────┘
```

关键决策：

- **任务详情用页面内抽屉，不用右侧栏 tab。** `sidebar.right.pane.tab` 是会话作用域的；全局待办在没有会话时打不开。抽屉在 `main` 页面内，零会话依赖。
- **提醒继续走“宿主持数据 + 客户端扫描 + 浏览器通知”。** `ctx.schedule` 的投递目标是会话（会创建/唤醒会话），不适合当本地任务闹钟；P3 可评估接系统通知。
- **数据仍以单 JSON 为单位。** 5k 任务以内足够；超过再迁到 `ctx.storage.domain` 的 SQLite 后端（接口不变）。
- **不引入 UI 组件库。** 拖拽、日历、图表用原生 React + SVG；样式只用 `--dsw-alias-*` / `--dsw-focus-ring-*`。

## 3. 数据模型 v2

```jsonc
{
  "version": 2,
  "revision": 128,
  "lists": [
    { "id": "inbox", "name": "收件箱", "folderId": null, "order": "a0", "color": null, "deletedAt": null }
  ],
  "folders": [{ "id": "f1", "name": "工作", "order": "a0", "deletedAt": null }],
  "tags": [{ "id": "t1", "name": "工作", "color": null }],
  "tasks": [
    {
      "id": "k2p1x9",
      "listId": "inbox",
      "title": "交周报",
      "notes": "附上 Q4 数据",
      "status": "open",              // open | completed
      "priority": 3,                  // 0 无 1 低 2 中 3 高
      "dueAt": 1795514400000,
      "startAt": null,
      "allDay": false,
      "reminders": [{ "id": "r1", "at": 1795510800000, "firedAt": null }],
      "recurrence": {                  // null 表示不重复
        "kind": "weekly",
        "weekdays": [1, 3, 5],
        "time": "18:00",
        "timeZone": "Asia/Shanghai"
      },
      "seriesId": null,                // 重复任务同系列
      "tags": ["t1"],
      "subtasks": [{ "id": "s1", "title": "补数据", "done": false, "order": "a0" }],
      "order": "a3",                   // 清单内手动排序（fractional）
      "estimateMinutes": 30,
      "spentMinutes": 0,
      "createdAt": 1795363904231,
      "updatedAt": 1795363904231,
      "completedAt": null,
      "deletedAt": null                // 软删除，撤销/回收站
    }
  ],
  "filters": [
    { "id": "f1", "name": "本周高优", "query": { "and": [
      { "field": "priority", "op": "in", "value": [2, 3] },
      { "field": "dueAt", "op": "between", "value": ["2026-11-23", "2026-11-29"] }
    ] } }
  ],
  "focusSessions": [{ "taskId": "k2p1x9", "startedAt": 1795363904231, "minutes": 25 }],
  "settings": {
    "defaultListId": "inbox",
    "weekStart": 1,
    "pomodoro": { "work": 25, "break": 5, "longBreak": 15, "rounds": 4 },
    "reminderScanSeconds": 30,
    "keepCompletedDays": 90
  }
}
```

约定：

- 时间一律存 epoch 毫秒；展示用本地时区，重复规则额外存 IANA 时区。
- `order` 用 fractional index（`a0`、`a1`、`a0V`），插入不需要重排全表。
- 删除一律软删除；撤销与回收站共用。`keepCompletedDays` 之后物理清理。
- 所有写操作带 `opId`（客户端生成），宿主按 `opId` 幂等，防重复提交。

## 4. 宿主 API

现有 `POST /dsh-sidebar-todo/state` 是“单操作 + 返回全量”。v2 改为命令式，仍是同一路由：

| 命令 | 入参 | 返回 | 说明 |
|---|---|---|---|
| `task.create` | `{listId,title,dueAt?,priority?,tags?,subtasks?,recurrence?,reminders?,opId}` | `{task,revision}` | 快速添加也走它 |
| `task.update` | `{id,patch,opId}` | `{task,revision}` | patch 白名单字段 |
| `task.complete` | `{id,opId}` | `{task,next?,revision}` | 重复任务返回下一次实例 |
| `task.uncomplete` | `{id,opId}` | `{task,revision}` | |
| `task.delete` | `{id,opId}` | `{revision}` | 软删除 |
| `task.restore` | `{id,opId}` | `{task,revision}` | 撤销删除 |
| `task.reorder` | `{id,beforeId?,afterId?,listId?,opId}` | `{revision}` | fractional 计算 |
| `task.bulk` | `{ids,action,patch?,opId}` | `{revision}` | 批量完成/移动/删除/加标签 |
| `subtask.*` | `{taskId,...}` | `{task,revision}` | 增删改勾 |
| `list.create/update/delete/reorder` | … | … | 删除清单时任务移到收件箱 |
| `tag.rename/merge/delete` | … | … | 合并标签 |
| `filter.save/delete` | … | … | 保存查询 |
| `query.list` | `{view?|query?,sort?,limit?,cursor?}` | `{tasks,total,nextCursor}` | 列表/看板/日历/搜索共用 |
| `stats.get` | `{from,to}` | `{byDay,byList,byTag,focusMinutes}` | |
| `focus.log` | `{taskId,startedAt,minutes,opId}` | `{revision}` | 番茄钟结算 |
| `state.get` | `{since?}` | `{revision,delta?|state}` | 增量同步 |

实现顺序：先保留“返回全量”，`since` 增量在 P2 数据量上来后再加；客户端按 `revision >` 应用。

## 6. 关键模块

### 6.1 智能清单与筛选

- 智能清单是**纯派生**，不落库：
  - 收件箱：`listId === inbox && status === open`
  - 今天：`dueAt <= 今天 23:59 && open`（含逾期）
  - 最近 7 天：`今天 < dueAt <= 今天+7 天`
  - 全部：`open`
  - 已完成：`status === completed`
- 自定义筛选存 `filters[].query`，查询 DSL：
  ```json
  { "and": [
    { "field": "priority", "op": "in", "value": [2, 3] },
    { "field": "tags", "op": "contains", "value": ["t1"] },
    { "field": "dueAt", "op": "before", "value": "2026-12-01" }
  ] }
  ```
  操作符：`eq/ne/in/contains/before/after/between/isNull`；字段白名单固定，避免任意表达式。
- 搜索：标题/备注/子任务标题的大小写不敏感子串；宿主端做，返回分页。

### 6.2 重复任务

- 预设统一编译为内部规则：
  ```ts
  type Recurrence =
    | { kind: 'daily'; every: number }
    | { kind: 'weekly'; every: number; weekdays: number[]; time?: string; timeZone: string }
    | { kind: 'monthly'; day: number; time?: string; timeZone: string }
    | { kind: 'yearly'; month: number; day: number }
    | { kind: 'rrule'; rrule: string }   // P4
  ```
- 完成时计算下一次到期：以“当前到期时间”为锚点，按规则推进到 `> now`；创建新任务（同 `seriesId`，`occurrence+1`），旧任务标记完成。
- 边界处理：月末（31 日 → 2 月取最后一天）、时区、夏令时（用 IANA 时区 + `Intl` 补偿）。
- P1 只做每天/工作日/每周指定星期/每月指定日；自定义 RRULE 放 P4。

### 6.3 提醒

- 每个任务最多 3 个绝对时间提醒，存 `reminders[]`；`firedAt` 防重复。
- 宿主不跑定时器；客户端插件级每 30 秒拉取一次状态，扫描 `at <= now && !firedAt`，批量通知，然后 `reminder.fire` 回写。
- 稍后提醒：10 分钟 / 1 小时 / 明天 09:00，改 `at` 并清 `firedAt`。
- 多窗口：`firedAt` 落库 + `revision` 同步，避免两个窗口各弹一次（仍有极小竞态，可接受）。
- 限制：应用关闭时不提醒；P3 评估 Electron 系统通知或 `ctx.schedule` 的 one-shot 方案（会创建会话，默认不用）。

### 6.4 视图

| 视图 | 实现 | 复杂度 |
|---|---|---|
| 清单 | 分组 + 虚拟滚动（>200 条时） | 低 |
| 看板 | 列 = 清单或优先级；pointer 拖拽；列内排序写回 `order` | 中 |
| 日历 | 月/周网格；任务按 `dueAt` 落格；拖拽改期 | 中高 |
| 四象限 | 紧急 = 逾期或今天到期；重要 = P2/P3；2×2 派生 | 低 |
| 时间线 | 不做 | — |

日历不接外部日历，先做“任务日历”；P4 再评估 ICS 导入（只读）。

### 6.5 番茄钟与统计

- 番茄钟浮层用 `shell.overlay`，选择任务后开始；状态存客户端，结束时 `focus.log` 落库。
- 统计从任务与 `focusSessions` 派生：
  - 近 30 天完成数（按天柱状图，SVG）
  - 按清单/标签分布
  - 专注分钟、连续完成天数
- 不做习惯打卡；不做跨设备统计。

### 6.6 Agent 能力

- 扩展现有 `todo_manage`：
  - `query`：按视图/筛选查询
  - `bulk`：批量完成/移动/加标签
  - `breakdown`：把一条任务拆成子任务（模型生成，一次调用写入）
  - `review`：今天/逾期/本周摘要
  - `plan`：把一段自然语言计划写成任务列表（先预览再确认）
- 新增系统提示词段落：何时读、何时写、不要和内置 `todo_write` 混淆。
- 捕获：`/todo` 命令把当前输入或选中文本变成任务草稿；agent 可在对话里建议“加入待办”，用户点确认才写。
- 所有写操作走同一宿主方法，UI 与工具不各写一套逻辑。

### 6.7 键盘与命令

- `Ctrl/Cmd+K` 命令面板（复用 DSH 命令系统）：新建任务、跳转清单、开始专注。
- `N` 新建、`/` 搜索、`J/K` 移动、`Space` 勾选、`E` 编辑、`Delete` 删除、`1–4` 设优先级。
- 全局快速添加：注册到 `ctx.shortcuts`，默认不占用系统冲突键，可在设置里改。

## 7. 分阶段路线图

| 阶段 | 内容 | 交付物 | 验收 | 估时 |
|---|---|---|---|---|
| **P0 基础重构** | v2 数据模型 + v1 迁移；清单/标签；任务 CRUD；智能清单；详情抽屉；撤销；`^清单` 语法（文件夹后置到 P1）；已完成物理清理改为 90 天 | 可用的 TickTick 骨架 | 旧数据无损迁移；新增/编辑/完成/删除/撤销全通；刷新不丢 | 2–3 天 |
| **P1 TickTick 核心** | 子任务、备注 Markdown、优先级 4 档、多提醒 + 稍后、重复任务预设、拖拽排序、搜索、批量、快捷键、i18n（zh/en） | 日常可替代 TickTick 个人版 | 重复任务连续完成 10 次到期正确；提醒去重；搜索 <100ms | 4–6 天 |
| **P2 视图** | 看板、月/周日历、四象限、保存筛选、统计页、增量同步 | 多视图任务管理器 | 拖拽改期/换列落库；1000 任务滚动流畅 | 4–5 天 |
| **P3 专注与 Agent** | 番茄钟浮层、专注统计、`/todo` 捕获、agent query/bulk/review/breakdown、每日回顾 | 有 DSH 差异化的版本 | agent 能查/改/拆任务；专注记录进统计 | 3–4 天 |
| **P4 可选** | 自定义 RRULE、ICS 只读导入、模板、附件、回收站保留策略、系统通知 | 增强项 | 按项验收 | 按需 |

总计约 **13–18 人日**；P0+P1 约 **6–9 人日**，即可得到“个人版 TickTick”的核心体验。

## 8. 迁移与兼容

1. 读取 v1 `{ todos: [...] }`，写 `state.v1.backup.json`。
2. 映射：
   - `text` → `title`
   - `priority` 1/2/3 → 3/2/1（高/中/低）；0 → 0
   - `dueAt` → `dueAt`；`tag` → `tags[0]`
   - `done` → `status: completed` + `completedAt`
   - 全部进 `inbox` 清单
3. 写 v2，`version: 2`；迁移幂等，失败不覆盖原文件。
4. 客户端按 `version` 分支渲染，至少保留一个大版本兼容。

## 9. 测试与验收

**单元测试（宿主）**

- 重复任务：每天/工作日/每周/每月；月末、闰年、时区、夏令时。
- 查询 DSL：每个操作符、组合、非法字段。
- 迁移：v1 各种字段组合、坏数据跳过。
- 统计：按天/清单/标签聚合；空数据。
- 撤销/软删除/恢复；`opId` 幂等。

**接口测试**

- 每个命令的成功/校验失败/冲突；`revision` 单调。
- 并发两个窗口写：last-write-wins 且不丢字段。

**手工验收**

- 新增 → 详情 → 子任务 → 提醒 → 完成 → 撤销。
- 1000 条任务滚动、搜索、切换视图。
- 浅色/深色、窄窗口、键盘全流程。
- 应用重启后数据与视图状态恢复。

## 10. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 范围膨胀成“完整 TickTick” | 交付延期 | 严格按 P0/P1 验收，P2+ 单独立项 |
| 日历/看板拖拽复杂 | 交互 bug | 先用原生 pointer 事件做最小拖拽；不行再引轻量库 |
| JSON 单文件膨胀 | 保存变慢 | 5k 任务或 2MB 时迁 `ctx.storage.domain` |
| 多窗口写冲突 | 丢更新 | `opId` 幂等 + 字段级 patch + revision 校验 |
| 应用关闭无提醒 | 漏提醒 | 文档写明；P3 评估系统通知 |
| 重复任务边界 | 日期错乱 | 用 IANA 时区 + 专门单测；不做跨时区迁移 |
| 中文文案/i18n | 非中文用户体验 | P1 接 `ctx.locale` 字典，面板 label 也走 `t()` |
| TickTick 闭源 | 法律风险 | 只参考交互，不复制代码、图标、文案 |

## 11. 不做清单

- 协作、共享清单、指派、评论。
- 习惯打卡、倒数日、纪念日。
- 位置提醒、移动端定位。
- 40+ 主题、自定义皮肤（跟随 DSH 主题）。
- 云端同步、多设备账号体系。
- 日历双向同步（P4 仅评估 ICS 只读导入）。
- 时间线/甘特视图。

## 12. 建议的下一步

1. **P0 第一刀**：数据模型 v2 + 迁移 + 清单/标签 + 详情抽屉。这一步完成后，现有 MVP 的“单清单”限制就解除了。
2. 同时补一套宿主单测（重复/查询/迁移），避免后面视图开发时反复回归。
3. P1 完成后再决定是否做日历/看板——这两个是工作量最大、收益最不确定的部分。
